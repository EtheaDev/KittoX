# Dolls

Every doll belongs to a girl - her **mom** - and that is the one thing a doll cannot be without.

## Dolls List

The list is **grouped by mom**. Above it, **Choose Mom** is a box that completes what you type:
type the first letter of a name, pick the girl, and the list is left with her dolls. Emptying the
box brings back all of them.

The toolbar is the usual one, plus **View**, which opens a doll without the risk of changing it.
The form opens over the list and carries the arrows to walk from one doll to the next without
closing it.

## What a doll is made of

| Field | |
|---|---|
| **Name** | The name of the doll. Required. |
| **Birth Date** | The day it was bought, which in this application is the day it was born. |
| **Hair** | One of the [hair types](hair-types). |
| **Dress Size** | A short code, four characters at most. |
| **Mom** | The [girl](girls) the doll belongs to. **Required**: a doll without a mom cannot be saved. |
| **Mom's Phone** | Shown beside the mom, and read from her: it is not typed here. |
| **Aspect** | A free description, as long as you need. |

## New Doll

**Dolls → New Doll** opens an empty form directly, without passing through the list. It is the
same form, and the same rules apply.

## Doll Catalog

**Dolls → Dolls Card** shows the same dolls as **cards** instead of rows - a picture each, with
the name and the main fields underneath. It is the same data: what changes is only how it is laid
out, and it is there to show that a list can be drawn any way an application wants.
